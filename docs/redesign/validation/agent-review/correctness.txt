## COR-001：优惠券在两个入口中均被加到小计，而不是扣除

- **根因类别**：算术方向 / 需求实现错误。
- **首次及当前候选**：此次固定的本地候选；无变更后的复审候选。
- **真实性**：本 reviewer 本地复现确认；交由未提出该项者作后续独立核验。
- **重要性**：当前功能正确性未满足。是本地产品行为问题，不因文件名将其升级为真实资金事故；不据此形成任何集成授权。
- **位置与实例**：
  1. [checkout_total:5](<../project/billing.py#L4-L5>)：`max(0, sum(amounts) + coupon)`。
  2. [preview_total:9](<../project/billing.py#L8-L9>)：同样的加法表达式。
- **要求依据**：[REQUIREMENTS:3](<../project/REQUIREMENTS.md#L3>) 明确要求减 coupon 后再与零取最大值。
- **可达前提及因果**：直接向任一公开函数传入可信的非负整数列表与正整数 coupon 即触发。设小计 `S >= 0`、优惠券 `C > 0`，当前表达式返回 `S + C`，外层 `max` 不会修正加法；当 `S >= C` 时比应有结果多 `2C`，当 `S < C` 时本应为零却返回正数。因此超过小计不能归零是同一算术根因的后果，不另立发现。

### 已确认复现

以下每行均直接调用两个入口，实际值两者相同：

| amounts | coupon | 契约期望 | checkout 实际 | preview 实际 |
|---|---:|---:|---:|---:|
| `[100, 50]` | 20 | 130 | 170 | 170 |
| `[5]` | 8 | 0 | 13 | 13 |
| `[]` | 3 | 0 | 3 | 3 |
| `[5]` | 5 | 0 | 10 | 10 |
| `[5]` | 0 | 5 | 5 | 5 |

额外有限穷举：列表长度 `0..3`，每个元素 `0..3`，coupon `0..9`；850 个输入组合。**每个入口各 765 次偏离契约，两个入口相互不一致次数为 0；85 个 coupon=0 的组合均正确**。另验证省略 coupon 时 `[5]` 返回 5。这里按入口计数，不把同一组合的两个错误结果重复当成独立输入。

可在实验目录复跑，不生成文件：

```bash
python3 -B - <<'PY'
import itertools
import sys
sys.path.insert(0, 'project')
import billing
n = bad_checkout = bad_preview = parity = 0
for length in range(4):
    for items in itertools.product(range(4), repeat=length):
        amounts = list(items)
        for coupon in range(10):
            expected = max(0, sum(amounts) - coupon)
            a = billing.checkout_total(amounts, coupon)
            b = billing.preview_total(amounts, coupon)
            n += 1
            bad_checkout += a != expected
            bad_preview += b != expected
            parity += a != b
assert (n, bad_checkout, bad_preview, parity) == (850, 765, 765, 0)
assert billing.checkout_total([5]) == billing.preview_total([5]) == 5
print(n, bad_checkout, bad_preview, parity)
PY
```

实际运行输出：`850 765 765 0` 对应的计数均通过断言，工具未返回异常。首次有限穷举用 tuple 序列，随后已用上面契约要求的 list 输入重新执行并确认同样结果；报告所列有限覆盖以 list 复验为准。
