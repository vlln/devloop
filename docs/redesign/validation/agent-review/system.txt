## SYS-001 — 两入口共同将 coupon 作为加价而非折扣

- **稳定 ID / 根因类别：** SYS-001 / 优惠券算术方向错误（共享行为类别，两个直接实现实例）。
- **首次 / 当前候选：** 均为上述 coupon 源码 SHA-256。本次为本 reviewer 首轮独立发现，不代表整个项目历史审查轮次。
- **依据：** [要求第 3 行](<../project/REQUIREMENTS.md#L3>)规定两入口返回 `max(0, sum(amounts) - coupon)`，超过小计时返回 0。
- **位置 / 已确认实例：** [checkout_total:5](<../project/billing.py#L4-L5>) 与 [preview_total:9](<../project/billing.py#L8-L9>) 都执行 `max(0, sum(amounts) + coupon)`。
- **前提 / 可达路径：** 直接调用这两个公开函数，输入均为契约允许的可信非负整数列表和非负整数；不依赖非法输入、负数、浮点、支付服务或未提供的外部调用者。
- **因果：** 对非负小计和正 coupon，`sum + coupon` 必为正，`max(0, ...)` 无法实现折扣后的零下限。两入口增加了本应扣掉的值；共同错误同时造成普通折扣错误和超过小计不归零。二者是一个根因，不拆成重复 finding，也不虚构入口不一致。

实际本地结果（两入口数值相同）：

| amounts | coupon | 要求值 | checkout | preview |
|---|---:|---:|---:|---:|
| `[5, 7]` | 3 | 9 | 15 | 15 |
| `[5, 7]` | 12 | 0 | 24 | 24 |
| `[5, 7]` | 13 | 0 | 25 | 25 |
| `[]` | 2 | 0 | 2 | 2 |
| `[0, 0]` | 3 | 0 | 3 | 3 |

- **真实性：** 确认：已执行上述实例，并枚举下述有限域；静态表达式可直接解释观测。
- **重要性：** 阻塞当前 coupon 功能按原要求接收；实际后果是本地产品计算错误，**不是已证实真实资金损失或生产计费事故**。
- **归因：** 根据固定事实，属于本次新增 coupon 路径，不是 label 或无关历史债；无历史 diff 的限制如上。
- **有限同类范围：** 已全文检查本项目提供的两项 coupon 入口（两处均确认），另检查 label 隔离语义。项目路径枚举仅有两个实现及两个契约文件，无其他本地调用者或测试文件可查。不推广到未提供的服务、包、第三方调用者或真实支付链路。
- **处置 / 责任 / 关闭依据：** 原始发现交协调者分配独立核验，不自行改代码或授予作者权限。建议核验后按单一根因处理两个入口；关闭需在实际修复候选重验普通正 coupon、等于 / 超过小计、零小计、零 coupon 和两入口一致性，同时保留旧调用及 label 有意行为。不要求新增折扣类型或大范围重构。

## 本地执行证据与回归边界

环境：本地 Python **3.9.6**；两个前台 `python3 -B -` 内存脚本通过 `importlib.util.spec_from_file_location` 加载上述源码；禁写 bytecode，不创建项目测试文件。运行均正常完成（工具未输出非零退出或异常；其 bash 返回格式未显示显式 `[exit code: N]` 标记，因此不捏造该标记）。负例差异被打印为证据，没有伪称全绿。

### 入口、兼容与零下限

1. 代表性 8 个 case × 2 入口：共 **16** 个要求对照，**12 失败**；失败均为正 coupon。包含空列表、零值、小于/等于/超过小计、大整数。大整数 `[10**40], coupon=1` 的两入口均为 `10**40+1`，要求 `10**40-1`，不是浮点精度问题。
2. 有限枚举：列表长度 `0..3`、各元素 `0..3`、coupon `0..10`，总计 **935** 个输入组合：
   - 两入口 parity：**0 / 935 失败**。
   - 要求值对照：**1700 / 1870 入口-case 检查失败**，全部是正 coupon 的 850 组合 × 2 入口。
   - coupon=0：**0 / 170 入口-case 检查失败**。
   - 脚本断言上述计数成立。
3. 对 `[]`、`[0]`、`[5,7]`、`[10**40,3]`：两入口各验证单参数、显式位置参数 `coupon=0`、关键字 `amounts=.../coupon=0`，共 **24** 次兼容调用全部等于 `sum(amounts)`。
4. `inspect.signature` 显示两个函数均为 `(amounts, coupon=0)`；因此当前候选仍支持单参数旧入口及同名参数，不报告无证据的 API 签名破坏。

有限枚举可复现核心（命令入口 `python3 -B -`；下列只读加载并在内存执行）：

```python
import importlib.util
from itertools import product
s = importlib.util.spec_from_file_location('billing', 'project/billing.py')
b = importlib.util.module_from_spec(s)
s.loader.exec_module(b)
n = parity = failures = zero_failures = 0
for size in range(4):
    for items in product(range(4), repeat=size):
        amounts = list(items)
        for coupon in range(11):
            expected = max(0, sum(amounts) - coupon)
            actual = (b.checkout_total(amounts, coupon),
                      b.preview_total(amounts, coupon))
            n += 1
            parity += actual[0] != actual[1]
            failures += sum(v != expected for v in actual)
            if coupon == 0:
                zero_failures += sum(v != expected for v in actual)
assert (n, parity, failures, zero_failures) == (935, 0, 1700, 0)
```

### label 负例控制

实际分别传入 `None`、`-7`、`0`、`3.5`、`'<b>&'`、`['x', -1]`、`{'x': -2}`，断言 `render_label(value) == str(value)`，**7 / 7 通过**。负数输出 `'-7'`、标记字符串输出 `'<b>&'` 正是要求，不是安全漏洞或需要“统一”的 coupon 输入错误。实现全文仅直接 `return str(value)`；有限动态样例不声称覆盖所有自定义对象，但静态路径没有额外验证、截断或转义。不对契约允许的 Python `str` 本身行为另造需求。
