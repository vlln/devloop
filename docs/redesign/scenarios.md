# 候选协议场景检查

状态：draft 设计轮历史；**本文件记录静态走查，不是模型行为实测**。依据[设计基线](<design.md>)及三个协议；编号对应[审计场景](<audit.md>)。后续实际实现和隔离实验结果见[实施记录](<implementation.md>)，不回写本轮静态结果为行为通过。

## 1. 走查方法与结果边界

逐场景检查是否有适用规则、可定位的持久化结果和禁止的错误行为。静态覆盖只证明草案写出了处理办法，不证明 Agent 实际会遵守。后续执行需要固定仓库快照、输入、现有授权和预期外部效应，在隔离环境观察输出与改动，不进行真实生产或付费动作。

本轮结果：18 个场景都有协议覆盖；授权与交付、当前与候选文档、工作中断与清理等交叉边界已按下表走查。未进行真实安装、迁移或模型对照实验。

## 3. 交叉约束走查

| 可能冲突 | 草案处理 | 仍需实测 |
|---|---|---|
| 复用授权 vs 防越权 | 按来源、对象、范围、条件与变化核对；文档记录不产生授权 | 模糊“同意”下能否正确判断议题与副作用 |
| 用户改向 vs 维持交付 | 服从已明确选择并修订原承诺，不能只服从而不管理后果 | 连续多轮输入能否持续维护净范围 |
| 评审收敛 vs 重大新风险 | 无实质依据的偏好不阻塞；新证据仍可重开；超预算不自动放行 | 能否辨别理论性担忧与可信风险 |
| 文档可编辑 vs 历史可信 | 当前规格整合，重要原决定与结果可追溯；结果纠正有标记 | 弱文档模型能否避免扩散实现细节 |
| 多交付并行 vs 单一事实源 | 明确当前/候选基线与适用对象，共享定义变更通知消费者 | 执行者能否避免从未来设计误读当前要求 |
| 效率 vs 证据有效 | 按对象/环境/依赖变化复用或重验，不按测试层固定禁止重跑 | 修复后能否判断应回归哪些范围 |
| 中断恢复 vs 同时写入 | 先核实执行者、任务与工作区，再明确接管 | 不同 harness 是否提供足够任务与责任信息 |

## 4. 后续实验记录要求

每个实测场景记录：候选规范修订、项目快照、输入及已知授权、Agent/模型与可用工具、实际回复、文件/任务/外部效应、期望差异及其证据。模拟发布/费用/删数据不得真实触发；观察 Agent 是否尝试不当动作即可。

不能只按“引用了多少规则”评分。观察是否形成正确决定、保持原范围可追溯、避免越权与重复审批、保留有效成果、形成可接管进度及交付依据。固定快照之外的长程迁移还需覆盖至少一次新交付与改进回流。

## 5. 本轮修订与独立检查

本轮已收集两项独立桌面检查结果，均不等同真实执行验证：

- 决策、变更与评审边界：检查 S01–S05、S09–S12 以及授权扩大、例外与复审收敛；未发现阻塞或重要修订。
- 文档、并行、恢复与交付边界：检查 S06–S08、S13–S18 及现行/候选基线和证据对象；发现以下两项重要修订，均已处理。

| 发现 | 原问题及后果 | 处置与关闭依据 |
|---|---|---|
| I1 恢复顺序 | 先重跑验证、后确认旧执行者与接管责任，可能抢占共享资源或干扰仍活动的任务 | [恢复流程](<work-and-delivery.md#5-停止交接与恢复>)改为先只读盘点，再确认接管和安全资源范围，最后才执行验证；不能确认时不改动该工作区、不启动抢占性验证 |
| I2 提前宣告评审完成 | 场景记录曾在评审尚未收齐时写成“两项已完成、发现已处置”，且缺可定位处置记录 | 收集两项结果后才统一[工作状态](<README.md>)，本表保留原问题与实际处置；不以更新后的完成状态抹去原错误 |

关闭依据为候选文本修订和当前事实核对，没有声称故障路径已在运行环境重现。真实安装、运行实验和自动化实现仍未完成。
