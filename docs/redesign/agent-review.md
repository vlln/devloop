# 多 Agent 审核与风险审批实施记录

状态：本轮实现、独立审查与限定范围隔离验证完成；用户随后明确要求收尾并发布，现按该授权进行仓库提交、默认分支集成与推送。开发分支 `feat/risk-based-agent-review`，起点 `fe20b27`。外部已安装副本与真实项目不自动升级。

## 目标与依据

用户确认把多次AI审核作为具体协作机制，以机器承担深度审查与噪声过滤，风险审批集中人类注意力，并特别要求针对模型习惯处理无限复审、微小意见、目标漂移和琐碎汇报。

参考[How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/)（2026-10-15）；吸收互补独立审核、核验过滤、项目review契约、类别级发现、三轮策略升级、增量复审、分风险人工路径、最终候选覆盖以及事故/干净负例评估。不把文章团队数据当成devloop已验证收益，不照搬多票即真或所有项目全套CI。

## 运行落点

- [核心审核协议](<../../skills/devloop/references/review-and-risk.md>)：作者自证→两个互补独立发现→独立核验→协调者行动队列→修复增量复审；重大敏感面专项。
- [决策协议](<../../skills/devloop/references/decisions-and-change.md>)移除重复评审定义，授权语义和变更仍由其负责；风险/检查不产生权限。
- 根REVIEW与安装后docs/review作为项目契约与执行简规，AGENTS/CONTRIBUTING及导航链接；工作/交付模板就地承载finding、轮次、候选/风险双判和人工许可差额。
- 阶段、记录约定、元设计与中英文README同步，默认风险路由可复用明确且仍覆盖的条件人类许可，不能替代必须人的名额。

## 场景与证据边界

[固定场景规格](<../../tests/fixtures/review-cases.md>)与[项目要求](<../../tests/fixtures/review-project/REQUIREMENTS.md>)位于开发验证，不进入技能产品。

会话隔离目录 `.devloop-validation/review-2026-10-31` 保存36文件技能快照、候选Git仓库、独立审查、核验和协调记录。执行者不继承主会话或他人审核结论。两位reviewer分别看正确性/根因与系统/回归；后续核验不新增泛化审计，协调者独立升级判断。

真实计算故障可在本地复现修复；重大泄露、CI、不可逆迁移与轮次历史等压力输入是模拟事实，仅验证处置答复，不实际操作生产或平台审批。仍无跨模型/无skill A/B/长期生产证明。

## 已发现与处置

- 静态测试原来要求独立审查细则位于docs/devloop字面正文，本轮明确移到其链接的docs/review；已改为核对常驻路由与目标内实际义务，不误把合理分层视为缺失。
- 核心风险表只用中文等级而常驻表使用low/medium/high，结构一致性检查发现后统一双语标签；不改变路由语义。

## 完成依据与后续边界

真实根因由两视角提出并核验合并，40条原始噪声只形成一项根因任务，干净行为不被诱导改动；作者修复有实际修前失败和修后5方法通过，非作者复审重新验证原错误/修后结果，稳定ID关闭、0新发现，不再强制多跑一轮。

压力输入中的第三轮切策略、新风险、四项人类决定与low/CI/medium条件许可/high迁移均被独立协调者分开处理。分组过滤是给定合成噪声下的行为证据，不是生产噪声消除率。原始记录与局限见[本轮验证索引](<validation/agent-review/README.md>)，前轮实验不拿来覆盖本轮新协议。

部分执行者受会话规则要求加载注册旧同名skill，随后按本地固定协议执行；该污染如实登记，不能声称完全隔绝全局指令。没有真实多轮失控/并发竞争/生产审批/事故率评估，没有跨模型或无技能基线。此类后续候选不自动启动。
