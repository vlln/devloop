# 工程选择提示与默认策略补充

状态：实现完成，定向行为验证结果见下文；不是重新安装或发布。

## 决定来源与修正理由

用户指出：模型知道操作方法，不代表知道本项目是否应采用，也不保证未经提醒会主动使用高质量控制。本轮明确同意据此补充工程选择点。它修正了先前“模型已知就可以删除”的过宽标准：删除教程，不删除行为激活。

运行规则由[工作协议](<../../skills/devloop/references/work-and-delivery.md>)定义，并在[入口](<../../skills/devloop/SKILL.md>)、相关阶段、常驻规则及工程约定模板落地。这里仅保存开发理由、检查范围和验证，不成为技能运行依赖。

## 实现

- 动手/切换任务/协作变化时，先只读判断分支、基线、未提交归属与活动执行者，选择继续当前分支、新分支或独立工作区。
- 优先原生策略；无策略时默认主干＋短期工作分支。首次建档可在主干，随后独立功能/重构/风险修复先建分支；有发布维护需要再加长期分支。不恢复 Gitflow 强制。
- 已在合适分支不再套分支；明确主干开发策略可沿用；低风险修正按许可简化；未知改动先保留，新分支不等于隔离已有文件与共享服务。
- 补触发矩阵：拆分/并行收益、关键未知最小实验、兼容迁移、行为风险验证、先失败复现再修复、重复约束自动化、最终 diff 自检、检查点、交付版本/观察/恢复。
- 首次选择进入工程约定，日常执行，事实变化重评；权限内自行决定，不逐项审批，不每次编辑重跑全套选择。
- Plan 增加起点基线和隔离/检查点选择及重要例外的落点。安装后 AGENTS 与简规保留主动判断正文，不只藏在会被移除的模板注释里。

## 验证方法

- 结构测试新增常驻工程选择覆盖，合计7项；不把文字匹配称行为证明。
- 固定快照放会话工作区 `.devloop-validation/engineering-choices-2026-10-30/devloop`，未更新用户安装技能。
- 四个真实本地 Git 夹具：干净 main 无策略、已有本任务分支、未知未提交用户文件、明确原生 main 策略。
- 执行者仅读安装后的 AGENTS/简规/工程约定和任务，用户只要求加 decrement 及必要测试；没有在任务中指定必须开分支。本地编辑/测试/分支/提交有明确模拟许可，无远端和全局配置权限。
- 脏目录的未知文件保护是实验明确边界，不将保全成功解释为技能独立因果收益。各夹具无活动写者，不是并发抢占故障注入。
