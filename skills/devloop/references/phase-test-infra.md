# TEST_INFRA：当期工程准备与自证

TEST_INFRA 为即将执行的工作提供可信的构建、验证、隔离与交付能力。它不是所有项目都要完整重建的一次性基建清单。

## 前提

- 当前交付及首批工作需要的基线、验收与验证方向可定位。
- 已识别现有工程能力、关键缺口、依赖和操作边界。
- 准备工作按[工作协议](<work-and-delivery.md>)认领；技术选择与外部资源操作按[决策协议](<decisions-and-change.md>)核对，不自动取得付费或生产权限。

## 动作

### 1. 对照当期需要检查能力

按真实交付方式确定适用范围，优先复用已有配置和有效自证：

| 能力 | 要确认的事实 |
|---|---|
| 构建与制品 | 所需依赖、构建入口和可识别产物可用 |
| 验证与数据 | 需要的测试驱动、数据、环境及结果采集可用 |
| 隔离与依赖 | 并行工作、Mock/真实依赖和敏感数据有适当边界 |
| 持续检查 | 项目当前需要的 CI、质量或架构约束能运行并反馈 |
| 交付与恢复 | 当期需要的安装、部署、观察和恢复路径可验证 |

先识别并运行已有适用构建、类型/lint与测试入口；对稳定、反复发生的重要约束，主动选择接入现有自动检查而非等待用户点名。结合缺陷与协作成本确定检查范围和阈值，无适用工具或收益不足时给替代依据。只补当前缺口；不为不存在的模块、服务或未来风险搭平台。重要工程取舍进入适当决定记录，普通配置不强制逐项 ADR。记录结构和术语遵循[记录约定](<records.md>)与[文档协议](<documentation.md>)。

### 2. 搭建并记录操作入口

维护必要配置、环境和开发/验证说明，使执行者能找到可运行入口、限制与负责人。不得只让能力存在于本会话或个人机器的隐式状态。

工程准备可包含最小测试或业务纵切片来验证能力；与 [DEVELOP](<phase-develop.md>)明确协作边界，避免重复实现。实验和占位用例不能冒充完整业务验收。

付费、配额、生产数据或破坏性外部调用须有授权和隔离边界。高频验证使用适当替身，真实依赖做有界核验；Mock 通过不能证明真实服务已经可用。

### 3. 自证能辨别对错

对新增或实质改变的关键能力提供有针对性的正向和反向证据，而不只证明进程可启动：

- 关键门禁对受控坏样例确实失败或阻断，而不是忽略失败退出码。
- 替身与共享契约一致；采集结果反映真实执行，而不是空报告或错误统计。
- 构建、环境及交付入口能对当期代表对象工作；恢复路径按风险验证。

受控坏样例不进入实际交付，不为了验证门禁擅自影响生产。按[证据与集成协议](<work-and-delivery.md>)记录对象、方法、结果与适用范围。

## 退出依据

- 即将开展的范围具备所需能力，缺口不被模板或占位配置掩盖。
- 新增/改变的关键能力已有自证；复用能力的证据仍覆盖当前基线与环境。
- 操作入口、约束、结果和责任可定位，重要决定与授权有效。
- 仍待准备的后续范围有明确依赖和工作，不阻塞无关就绪工作。

保存准备结论并推进相关 [DEVELOP](<phase-develop.md>)工作。无需重复搭建或全量自证已有效覆盖的能力，也不能将局部准备成功写成全部未来基建就绪。

## 增量与异常

- 新需求改变验证或交付能力：按[变更协议](<decisions-and-change.md>)检查差额，只补受影响部分。
- 验收发现门禁、环境、替身或数据问题：修复对应能力并重验相关证据，不全项目倒退。
- 基建选择暴露契约不可行：将受影响决定交回 [DESIGN](<phase-design.md>)处理，暂停依赖它的声明与工作。
- 资源或权限不可用：记录阻塞与替代建议，不静默跳过必要验证或自行扩大资源使用。
