# 多 Agent 审核、风险审批与反馈

目标：把充分的机器审查留在机器内部，把真实缺陷和重大后果凸显给人。不能以发现数、重复轮次或报告长度代替质量，也不能用“省人”绕过实际授权。本协议规定执行机制；需求与许可语义见[决策协议](<decisions-and-change.md>)。

## 1. 项目审查契约与输入包

项目采用根 REVIEW.md 或原生等价载体，按模块需要细化，保持短小：本区域主要失败模式、适用约束/已接受取舍、证据要求、生成/第三方等排除范围、敏感区域与审批下限、验证入口。不复制实现手册；排除扫描路径不能屏蔽来自这些路径的真实影响。没有项目契约时从现有规范提取最小审查包，不虚构 code owner 或历史政策。

每轮明确：目标/非目标、原基线与候选修订、相关契约、可执行验证及盲区、已知发现/处置、当前轮次与结束条件。审查者回报实际加载的适用契约和覆盖边界；协调者核对是否执行了其中的重点，不以“文件读过”认证遵循。

可以为理解影响读相关全仓上下文，但本轮整改范围不是全仓审计。早期提出方向/范围反馈；已完成候选的代码评审不借机强推未采纳未来架构。新证据确实推翻目标时进入变更协议。

## 2. 默认协作流水线

### A. 作者先验证

提交审查前运行适用构建/测试，展示实际输出与候选，做 diff 自检。提供“测试了什么、风险是什么、如何安全撤回/恢复”，不只说完成。检查不能覆盖什么也要说明。

### B. 独立发现

一般实质行为或共享规则变更，默认并行启动两个互补、上下文独立的审查者：

1. 正确性、需求满足、缺陷根因与同类实例。
2. 系统适配、接口/数据兼容、跨模块回归与实际消费路径。

涉及信任边界、鉴权、资金、敏感数据、CI/发布/安装更新时，加安全或领域专项视角，不让安全仅依赖普通 reviewer 顺便想到。人员可兼任不同阶段职责，但同一作者“换角色”不计独立审核；初始 reviewer 不共享彼此结论，避免锚定。

小型、可确定、低影响且项目允许的变更可用一个快速独立检查配合确定性工具；记录裁剪理由，不为省调用把实质变更伪称微改。工具不足时可串行调用新的独立上下文；若根本不能独立审核，记录降级/缺口，遵守项目门禁，不能声称多 Agent 已完成。风险允许的例外由有权者决定。

任务不是“找至少几个问题”。允许明确输出“0 项确认问题”，不因空结果再强制找一轮。普通疑点作为原始发现留给核验，不能直接要求作者修改。

### C. 独立核验与过滤

发现集合交给未提出该项的独立核验者/核验组；可批量核验，不要求每项额外一名 Agent。核验不是再次开放找茬，须逐项对照代码/调用者/契约：

- 事实和位置是否准确，故障前提是否可达？用测试、静态因果或可信风险推理验证，不凭函数名猜测。
- 行为是否有意、已接受，还是违反当前要求？建议的修复会不会破坏正确行为？
- 本次引入/加剧还是既有问题？严重后果与整改范围分别判断。
- 这个发现是否足以改变本轮实现、接收或风险决定？

核验可判确认、待验证、误报/有意行为、重复或丢弃。多数认可不能替代证据；一个有据的重大问题不因其他 Agent 没发现而被投票抹去。重大但不确定的项保持待验证及所阻塞关口，不掩盖以换取干净报告。

默认丢弃纯命名/风格偏好、无行为收益的清理、已由工具精确处理的重复诊断、没有因果路径的猜测及未采纳远景。真实项目硬约束与实际消费者影响另判，文档/配置也可能高风险。不把被丢弃 nit 自动转 backlog，不让作者“顺手全改”。

### D. 统一处置与增量修复

协调者形成一份去重后的可行动队列，按根因/独立修复单元聚合，不把原始 reviewer 报告拼接给作者或人。默认只实施核验后进入当前范围的问题；建议若改变目标、接口或重要取舍，先处理变更决定，不以整改为名扩重构。

每项发现有处置与依据；修复、有意/误报、重复、范围外、被替代、显式例外/延期分别保留，不假装所有项都修了。普通既有债单独记录或丢弃，不阻塞本次；已确认重大既有安全/数据风险须有归属和处置，不能以“非本PR引入”忽略。需要隔离/暂停受影响发布时明确说明，修复范围另定。

### E. 复审并收敛

首轮覆盖当前变更的完整相关影响；后续默认只核验原发现的关闭和“上次已审候选→当前候选”的增量及影响。未修改的上下文可读取，但不因此重新执行全仓发现任务。

默认第三轮结束仍未闭环时，**停止常规作者—reviewer 循环**。协调者辨别重复小问题、遗漏同类实例、修复回归、方案缺陷还是目标漂移，转为根因/类别级修复、一次定向验证、拆范围或重新设计；必要时向有权者升级。下一次工作必须说明新策略与未解阻塞，不能重置计数冒充首轮，也不能第四轮照常全量扫描。项目可因已识别高风险另定预算，但须有明确范围/理由，而非默认无限轮次。

轮次按完整审查—处置—核验周期计，不按 Agent 调用个数。通过后不因“通常要多审几轮”继续。新实质风险/新证据仍可重开，轮数上限不是自动通过或安全豁免。

## 3. finding 身份与证据

在原生 review threads 或工作 Report 维护最小账本，不强制每项一个文件。字段：稳定 ID、根因类别、首次/当前候选、要求/风险依据、位置和已确认实例、故障前提/证据、有限同类核查范围、真实性、重要性、归因、处置/关闭依据与责任。

三个轴独立：

| 轴 | 表达 |
|---|---|
| 真实性 | 确认、待验证、误报/有意行为；重复引用原 ID |
| 重要性 | 阻塞、重要可安排、琐碎/不行动；由实际后果决定 |
| 归因 | 本次引入/加剧、相关既有、无关既有 |

同一问题换说法或跨 reviewer 提出，合并原 ID；已关闭问题只有新证据或前提失效才重开，不因换审查者重开。发现 bug 类别时列已确认实例，并限定本次改动涉及的同类核查范围，不能把“待查”写成“都有bug”，也不能借类别修复要求全仓重构。

重要待验证项关系到当前完成条件时仍阻塞相关关口。风险接受不能把失败测试变 PASS；改变硬要求要走变更协议。批量噪声可按类别给丢弃数量与理由，不必为每个标点建议造 ID；重要发现、争议与重开必须可追溯。

## 4. 风险分类与人类审批

### 独立判级与升级检查

按实际 diff、依赖/调用者、暴露面、数据/资金/权限影响、可逆性、验证覆盖与未知判级，不按作者身份、行数或扩展名。信任/来源影响能否采用轻量路径，但不能降低变更本身风险。

作者提供事实；由非作者先做风险分类，再由另一个独立上下文做“即使低/中风险是否仍需升级”的检查。可复用审查者承担这些后续职责，但第二判断不由同一上下文自我盖章；提供候选和首判理由，主动核对敏感路径与遗漏影响。

项目在 REVIEW.md/工程约定标敏感面与审批下限。默认鉴权/权限、计费/资金、CI、发布/安装/自动更新及安全边界至少需要人类决定；破坏性数据操作、不可逆迁移、凭证/隐私暴露和广泛兼容破坏按高风险处理。不是每次出现这些词都危险，要定位真实变化；也不能靠改在文档/配置中躲开下限。

分级冲突先定向核验。实质影响仍不清时按较保守路径或升级，不把原始低置信小猜测全部推给人。

### 默认审批路由

| 等级 | 条件及默认路径 |
|---|---|
| low（低） | 局部、可验证、易撤回，无保留敏感事项/重大外效；核验和适用检查通过，且项目已有自主集成授权时，不要求新增人类批准 |
| medium（中） | 一般产品行为、共享边界变化或有一定影响面但恢复清楚；由一位有权的人决定，AI 先消化核验和证据 |
| high（高） | 重大安全/资金/数据/广泛兼容/不可逆影响；专项审核与恢复依据先齐备，人明确决定；项目政策可要求额外独立人类复核，不让 Agent 填人类名额 |

这是项目选择的默认路由，不是自动授予 Agent 合并/上线权。项目更严格政策、未知/不受信来源限制与人类保留事项优先。初始化不必逐条问审批矩阵；采用默认并记录，项目授权不清时只确认需要的自主路径。

已有明确人类决定/条件许可确实覆盖风险、候选范围与动作时，可复用，不重演审批。**授权覆盖和质量证据分别核对**：方向决定可以持续有效，review/risk/tests 只覆盖已审候选及经判断仍有效的部分。新提交、手工冲突解决、环境/迁移变化要差额复审及再判级；必须人类审批的最终候选未被覆盖时重新请求差额。项目规定 commit 级批准的，严格按其执行。

未处置阻塞、敏感升级未完成、必要验证缺失或许可不覆盖时不得集成/发布。自主集成不自动包含 push、部署、费用或删数据；按实际许可判断。

## 5. 三种输出，不让噪声占用人的注意力

1. **内部记录**：保存原疑点、核验、去重与处置；批量 nit 用类别计数，不输出长篇转储。
2. **作者队列**：只给已核验、属于当前范围的可行动事项，按根因聚合，含影响/证据/关闭条件；待验证重要风险单独分配核验，不先盲修。
3. **人类简报**：开头给确认/未解阻塞计数及当前结论，然后只展开人必须决定的重大后果、取舍或权限缺口，默认最多3个决策点；超出按共同决定分组或明确分批，不隐藏阻塞。已修复项一行汇总，误报/nit/重复只给总体处置或证据链接，不逐条问人。

请求决定包含：为什么需要人、候选/影响与最坏后果、机器已验证及盲区、恢复/剩余风险、推荐与具体问题。无须人的路径明确“无未处置阻塞，在现有授权内继续，无需回复”。0项确认问题是合法结论，不补写无价值建议充数。

## 6. 集成后责任与评估回路

合入者/当前交付责任方保持观察和修复归属；责任可明确交接，不能以 Agent 会话结束留下无人负责。按风险用小改动、特性开关、分阶段暴露、集成候选/merge queue 与有验证的恢复路径，工具是选择建议而非全部项目强制；敏感/不可逆影响不因易回滚口号降级。

重复出现的真实问题修到根上：适用 lint/test/CI、项目审查契约或 skill；不要永久靠 reviewer 反复念同一意见。事件/回退记录应问“哪层本该发现、缺什么上下文或检查”，形成有确认缺陷与位置的评估案例。加入已知干净/有意行为负例，检测误报与诱导有害修改；review prompt、工具或模型改动时复跑代表集合。

观察真实检出、漏检、误报/有意/不重要处置、修复导致错误、轮次、人工等待和交付后回退/事故代价。采纳率不是真值，Agent可能盲从。优先真实bug，再减少轮次；若省审批却增加事故/修复负担，不能称节约人力。小项目可在 Report 留简表，大项目用原生平台，不强制建仪表盘。
