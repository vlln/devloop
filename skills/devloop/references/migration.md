# 升级旧版 devloop 与原地接入

适用：项目已有六阶段 devloop 资料或正在运行的专业开发流程，需要采用当前协作协议。与[INIT](<phase-init.md>)配合；不通过批量替换旧词表假装迁移完成。

## 先保留事实

1. 读取项目原生规则、在途工作、当前交付/版本、分支/工作树与可用证据。先只读盘点，确认接管责任后再运行有副作用的验证。
2. 核对当前项目真正采用的技能/规则版本。仓库技能被修改不意味着外部已安装副本或所有项目自动升级。
3. 保存旧基线与重要决定来源；代码配置只能证明现状，不能补造选型理由，测试也不能证明原需求全覆盖。
4. 建议增量接入范围与实质影响；已有明确迁移授权可复用，无法确认的生产操作不在迁移中顺手执行。

## 语义映射

| 旧表示或约束 | 当前处理 |
|---|---|
| docs/README 只有一个阶段 | 先关联到正在推进的交付，补活跃工作/决定/恢复链接；并行交付分别跟踪 |
| 每次 DESIGN 末统一重新批准 | 判断既有决定和操作授权是否覆盖，只问缺口；不追溯编造批准 |
| 所有 accepted/active 一律不可改 | 当前规格受控整合；重要决定保留当时理由和替代关系 |
| Spec/AC 只追加 | 整理成一致当前版本，保留变化锚点与适用范围 |
| Plan pending/done，失败也 done | 逐个从证据辨别在制/结束与结果；旧 done 不自动转换 succeeded |
| Report done/complete | 映射为记录完整程度，保留实际成功/失败，不以状态词推断验收 |
| backlog 只有工程候选 | 可加入待澄清候选区；未定想法不自动进入本轮承诺 |
| 阶段唯一测试执行点 | 复核候选/环境/依赖与相关变化，复用有效证据，按影响回归 |
| 崩溃即丢弃工作树 | 先保全/核实/认领，未提交成果不默认丢弃 |
| 强制 Gitflow/文档代码拆 commit | 沿用实际策略；保留隔离、集成验证、可追溯且一致的交付候选 |
| 生成全部模板、所有项目回 DESIGN | 按现状识别已满足与未满足条件，增量补齐，不重写历史或制造已就绪假象 |

文档 ID、commit 与发布记录不为词表美观而重编号。状态可以暂保留旧词，但在项目入口或常驻规则说明含义，不能保留两套矛盾生效规范。

## 实施顺序

1. 更新 AGENTS 与常驻协作规则，让不加载 skill 的执行者也能处理新输入、授权、文档协作、变更与恢复。
2. 建立当前交付记录或映射现有载体；补本轮范围、条件、决定/授权来源、活跃工作与下一步。
3. 整理现行规格与接口适用范围，补必要的工作责任/依赖和证据对象；原本未知的事项继续标未知。
4. 同步项目贡献规范中与新协议冲突的绝对规则；保留项目自己有理由的更严格策略，除非有权者决定变更。
5. 检查索引/模板引用、当前与候选隔离和未完成迁移项，在入口标明采用版本与范围。

## 接入完成的依据

让未参与迁移的接手者仅凭项目资料说明：当前交付与剩余承诺、有效决定和许可边界、在途责任/资源、未决风险、证据状态、下一步。再处理一项范围变化与一次交接，观察记录是否同步；不能以目录存在或全部 frontmatter 合法宣告成功。

可以部分迁移并明示边界，不能声称所有历史已重验或所有旧授权已认证。迁移不附带发布、费用、数据操作或外部项目变更许可。
